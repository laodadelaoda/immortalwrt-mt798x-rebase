# EasyMesh 001–021 补丁维护与合并审议

基准分支：`n60pro-mtk-closed-driver`

审议基准：`vendor-sources.lock.json` 当前 `easymesh` patch set。

## 结论

本次不直接把 21 个补丁压缩成少数大型补丁。采用“维护分组 + 原子补丁 + Lock 唯一执行顺序”的结构。补丁分组只服务于上游升级定位，不参与源码变换，也不替代标准 `.patch`。

当前 Lock 定义：
- Build/Prepare application 阶段 19 个补丁；
- post-normalize 阶段 2 个补丁（006、001）；
- 总计 21 个补丁。

必须继续以 `vendor-sources.lock.json` 的 `application_order`、`post_normalize_order` 和 `post_normalize_root_suffixes` 为唯一执行依据。不得按编号排序，不得把 post-normalize 补丁提前。

## 可以考虑合并的候选

### A. 013 并入 011（WAPP WTS 同一解析函数）

两者都修改 `wappd/common/main.c` 中的 WTS 解析路径。013 的两个变更分别是 malformed hidden-SSID 输入改为 fail-closed，以及移除在 011 已增加前置容量检查后变成冗余的旧容量分支。

这是目前最明确的合并候选。但不能直接拼接 patch 文本：必须以锁定的 WAPP 原始归档为基线，重建合并后的目标文件，再从原始文件生成新补丁，证明零 fuzz、零 offset、零 reject、零部分应用。合并后从 Lock 中移除 013，并同步清单；原补丁文件及 SHA256 应保存在审计历史/归档记录中，不得静默丢弃。

### B. 009 并入 002（同一 DPP 配置读取函数）

002 与 009 都修改 `wappd/common/main.c` 中的 DPP 配置读取流程。009 主要处理 MAP_R3 条件编译下的变量作用域和无用 cred_len 清理，适合评估并入 002。

这项合并的前提是对完整 MAP_R3 / 非 MAP_R3 预处理结果进行比较，并在固定 WAPP 原始归档上重新生成补丁。不得仅凭补丁文本相邻或同文件就合并。

## 必须保持独立的补丁

- 007：OpenSSL 3.x EVP_PKEY API 兼容，独立 API 边界。
- 010、017、018：虽涉及相同 DPP 配置/凭据生命周期区域，但分别处理对象复制回滚、凭据边界与清零、跨多个 DPP 翻译单元的日志和生命周期。它们之间需要依赖/所有权审计，不应压成一个难以定位的大补丁。
- 015：配置查找 NULL / 错误返回边界。
- 016：QR URI 计数、读取、保存、删除及回滚事务。
- 011 与 012：是两份不同源码树中的 WTS 解析器（WAPP 与 1905daemon），必须分别重放和回归。
- 014：WPS key 日志脱敏，独立日志出口。
- 003、005：不同源文件中的 GCC14/内存操作修复，保持可独立回归。
- 004、006：分别是 libmapd 和 1905daemon 子 Make 构建参数，不跨目录合并；006 还必须保留 post-normalize 阶段。
- 019、020：虽然都触及 `wappd/map/map_1905.c`，但一个是报文/缓冲区安全，一个是 packed member 对齐访问，保持独立。
- 021：无线模式能力宏适配，保持独立。
- 001：DSA/Linux MII ioctl 修订，必须保留 post-normalize root=`1905daemon`。

## 上游升级时的维护流程

1. 固定原始供应商归档并核对 Lock SHA256。
2. 按 Lock 的真实阶段和顺序执行完整补丁重放。
3. 对每个补丁记录目标文件、目标函数、所属组件、前置依赖和回归测试。
4. 先检查同文件/同函数重叠，再判断能否合并；不能只按文件名或编号判断。
5. 如合并，必须从原始归档生成新补丁，禁止手工拼接 hunk。
6. 对合并前后最终源码做语义差异审查，并执行零 fuzz / 零 offset 重放。
7. 运行对应组件回归测试；最后执行供应商全集审计。
8. 只有全集审计凭证与当前 commit、Lock 和输入文件哈希一致，Quick 才能继续；Quick 成功后才允许 Full。

## 本次审议范围与限制

本次提交只增加维护分组说明，不修改任何现有补丁内容、供应商归档地址、SHA256、Lock 中的补丁顺序或 Quick/Full 门禁。两个合并候选尚未执行源码级合并；在完整原始归档重放和回归验证前，保持原补丁序列不变。
